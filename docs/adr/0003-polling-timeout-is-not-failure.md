# 轮询超时不判失败

轮询按 1.5 秒间隔进行，遇 `429` 按 2→4→8 秒指数退避（8 秒封顶）。单次生成的总轮询上限为 10 分钟，但**超时不会把生成任务标记为失败**：任务在服务端仍在继续，本地只是把控制权交还给用户，界面转为"继续等待"按钮，并保留视频 ID 供随时续查。同理，刷新页面或关闭窗口不中断服务端任务，历史记录里的未完成任务在重新打开时会被恢复为可续查状态。

**Consequences**

- 本地状态必须有 `pending`（等待中）之外的第五种：`unwatched`（已停止轮询但服务端可能仍在跑）。把它当成 `failed` 是错误的，会导致用户重试并重复计费。
- `failed` 只能由两类证据产生：服务端返回 `status: "failed"`，或创建任务本身失败。
