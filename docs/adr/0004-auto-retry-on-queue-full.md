# 创建任务遇到 503 队列满时自动重试两次

实测 `POST /v1/videos` 会返回文档未记载的两类失败：`503 {"code":"video_queue_full"}` 与 `429 rate_limit_exceeded`（免费档单用户限流）。两者都不是参数错误、不产生费用，且都在几十秒后自行恢复。因此创建流程内建 2 次自动重试：503 间隔 30 秒、429 间隔 60 秒，界面显示倒计时横幅。轮询侧的 502/503/504 同样走退避而非终止。

**Considered Options**

- 直接报错让用户手按：把本可自愈的拥塞变成用户负担，且免费档很容易连续撞上。
- 重试无限次：队列可能长时间满，无限重试让用户失去控制感，也掩盖了真实的服务不可用。

**Consequences**

- 错误文案必须区分"队列拥塞"与"参数非法"——前者不该让用户改提示词。`httpError` 因此优先按 `code` 分流，再按 HTTP 状态码兜底。
- 这两类错误的原始 JSON 形状是顶层 `{code, message, data}`，与文档描述的 `{detail}`、`{error:{message}}` 都不同，`extractRaw` 必须同时兼容三种。
